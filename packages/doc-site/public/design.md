# 项目设计规范（DESIGN.md）— 温润青玉主题

> 本文档用于小程序、H5 与 App 项目的 UI 设计和前端实现。
>
> 整理日期：2026-08-03  
> 主题版本：2.0.0「温润青玉」  
> 视觉方向：参考腾讯元宝的暖白底色、褐黑文字、青绿—青蓝有机渐变和克制留白，并针对出行产品重新设计  
> 源设计文件可见最近更新：2025-04-21（新增/更新自定义标题栏支持）

---

## 1. 文档目标

本规范将组件库转化为可执行的产品与工程约束，解决以下问题：

1. 新项目在颜色、字体、间距、圆角、图标和组件交互上保持统一。
2. 优先复用已有组件，避免重复设计按钮、弹窗、浮层、表单等基础能力。
3. 设计稿、组件代码与业务页面使用相同的语义化 Token。
4. 对小程序、H5、App 的系统栏、安全区和交互差异进行统一约束。
5. 为设计评审、代码评审和测试验收提供可检查的标准。

本文档不是单个页面的视觉说明，而是项目级设计系统的默认规则。

---

## 2. 适用范围与优先级

### 2.1 适用范围

- 微信、支付宝、抖音、快手等小程序
- 移动 H5
- iOS / Android App 内嵌页或原生页面
- 机票、火车票、酒店、用车及其他出行业务

默认不用于桌面端后台系统。若项目包含桌面端，需要另外建立桌面布局、密度、键盘操作与响应式规范。

### 2.2 规范优先级

发生冲突时，按以下顺序处理：

1. 当前业务需求中的强制规则与合规要求
2. 组件库中的最新已发布组件
3. 本 `design.md`
4. 项目局部约定
5. 开发者临时实现

局部页面不得无说明地覆盖全局 Token。确需差异化时，必须在项目的“设计例外”章节记录原因、作用范围和退出条件。

## 3. 核心设计原则

### 3.1 一致性优先

- 同一语义使用同一颜色、图标、组件和交互。
- 相同操作不得在不同页面使用不同形态或不同文案。
- 已存在组件时不得重新手绘相似组件。

### 3.2 信息层级清晰

- 页面中只能有一个最主要操作。
- 通过字号、字重、颜色和留白建立层级，不依赖过度装饰。
- 弱信息使用次级文字色，禁止通过任意降低透明度制造不可控颜色。

### 3.3 操作可预期

- 按钮、输入项、浮层和弹窗必须具备完整状态。
- 用户触发异步操作后必须立即显示反馈。
- 关闭浮层、取消操作和返回路径必须明确。

### 3.4 移动端优先

- 优先保证单手操作、触控热区、安全区和小屏内容可读性。
- 不直接照搬桌面端信息密度。
- 页面必须兼容系统字号、长文案、窄屏和底部安全区。

### 3.5 温润青玉视觉原则

- 页面以暖白和白色表面为主，青绿—青蓝仅用于关键操作、选中状态和品牌视觉。
- 褐黑文字替代纯黑，形成更温和、自然且具有亲和力的信息层级。
- 有机渐变用于品牌图形、重点视觉和少量特色操作，不大面积铺满普通页面。
- 主要按钮默认使用可访问的深青玉纯色；亮青绿渐变按钮必须搭配深色文字。
- 危险、警告、成功和信息状态使用独立语义色，不由品牌色临时推导。
- 大圆角、轻边框、低透明阴影和充足留白共同构成主题气质，禁止堆叠高饱和装饰。

## 4. Design Tokens

所有视觉值必须通过 Token 使用。业务组件不得散落硬编码色值，也不得在业务页面中自行生成品牌渐变。

### 4.1 主题核心色

| Token | 色值 | 用途 |
|---|---:|---|
| `--color-brand` | `#14C773` | 品牌识别、图形、进度、高亮装饰 |
| `--color-brand-strong` | `#08795A` | 主要按钮、选中状态、可访问文字和图标 |
| `--color-brand-cyan` | `#68D8DE` | 品牌渐变终点、信息装饰、科技感视觉 |
| `--color-brand-mist` | `#B8E2DA` | 插图、品牌浅色面积、次级装饰 |
| `--color-brand-soft` | `#E2F7EF` | 浅色标签、选中背景、轻提示背景 |
| `--color-info` | `#157A88` | 信息提示、可点击信息入口 |
| `--color-link` | `#0B7C79` | 纯文字链接与可跳转文本 |
| `--color-vip` | `#8A5B20` | VIP、专享权益和高价值服务 |

使用约束：

- `--color-brand` 是视觉识别色，不直接等同于所有按钮背景。
- 白色小字号文字只允许放在 `--color-brand-strong` 等通过对比度检查的深色背景上。
- 亮青绿和青蓝背景默认使用褐黑色文字 `--color-text-primary`。
- 普通链接使用 `--color-link`，不能仅通过颜色与正文区分，必要时增加下划线或跳转图标。
- VIP 色不得用于普通价格、折扣或通用强调。

### 4.2 语义状态色

品牌色和业务状态色必须解耦。

| Token | 色值 | 用途 |
|---|---:|---|
| `--color-success` | `#08795A` | 成功、完成、有效状态 |
| `--color-danger` | `#C73851` | 错误、失败、危险操作、紧急警示 |
| `--color-warning` | `#9A5A00` | 风险提醒、待处理、注意信息 |
| `--color-info` | `#157A88` | 普通信息、说明和推荐提示 |

规则：

- 状态必须同时使用文字、图标或结构表达，不能仅依赖颜色。
- 营销强调不得复用危险色，促销场景优先使用品牌渐变、VIP 金或独立营销组件。
- 状态浅色背景由预定义 Token 提供，不允许通过整个组件 `opacity` 实现。

### 4.3 中性色与表面色

| Token | 色值 | 用途 |
|---|---:|---|
| `--color-text-primary` | `#261208` | 标题、正文、关键数字 |
| `--color-text-secondary` | `#7B6F67` | 二级文字、辅助正文 |
| `--color-text-tertiary` | `#91867E` | 占位符、非关键提示；不用于必要小字号正文 |
| `--color-text-disabled` | `#C8C2BD` | 禁用文字、弱化图标、不可用状态 |
| `--color-page-bg` | `#FBF9F5` | 页面主背景、暖白画布 |
| `--color-surface` | `#FFFFFF` | 卡片、弹窗、浮层、输入区域 |
| `--color-subtle-bg` | `#F2F0EC` | 搜索区、分组区、次级背景 |
| `--color-selected-bg` | `#EDE9E4` | 列表选中、悬停和轻交互背景 |
| `--color-divider` | `#EBE6DF` | 普通分割线、轻边框 |
| `--color-divider-strong` | `#DED7CF` | 强分割线、区块边界 |
| `--color-overlay` | `rgba(38, 18, 8, 0.60)` | 弹窗与浮层蒙层 |
| `--color-shadow` | `rgba(38, 18, 8, 0.08)` | 卡片和悬浮组件阴影 |

### 4.4 青玉色阶

色阶必须保存为实体色 Token，不在运行时使用“原色 + opacity”生成前景色或背景色。

| Token | 色值 | 建议用途 |
|---|---:|---|
| `--color-brand-900` | `#075E45` | 深色文字、深色状态 |
| `--color-brand-800` | `#08795A` | 主要按钮、选中状态 |
| `--color-brand-700` | `#0B996A` | 按压态、深色图标 |
| `--color-brand-600` | `#10B574` | 实心高亮 |
| `--color-brand-500` | `#14C773` | 品牌标准色 |
| `--color-brand-400` | `#43D391` | 品牌图形 |
| `--color-brand-300` | `#73DEAF` | 浅色进度和插图 |
| `--color-brand-200` | `#A5E9CE` | 浅色块 |
| `--color-brand-100` | `#D6F4E8` | 选中背景 |
| `--color-brand-50` | `#EEFBF6` | 极浅提示背景 |

### 4.5 渐变规则

```css
--gradient-brand: linear-gradient(135deg, #14c773 0%, #68d8de 100%);
--gradient-brand-soft: linear-gradient(135deg, #d6f4e8 0%, #e5f7f7 100%);
```

允许使用渐变的场景：

- 品牌标识和抽象品牌图形
- 页面首屏重点视觉、AI/智能推荐入口
- 空状态插图、加载视觉和重要里程碑
- 经过设计确认的特色按钮

禁止使用渐变的场景：

- 普通表单、输入框、分割线和大面积正文背景
- 同一页面中的多个竞争性按钮
- 错误、警告等需要稳定识别的语义状态
- 小字号白色文字无法满足对比度的区域

渐变按钮必须使用 `--color-text-primary` 深色文字；普通主按钮默认使用 `--color-brand-strong` 配白色文字。

### 4.6 CSS Token 基线

```css

  --color-brand: #14c773;
  --color-brand-strong: #08795a;
  --color-brand-cyan: #68d8de;
  --color-brand-mist: #b8e2da;
  --color-brand-soft: #e2f7ef;

  --color-success: #08795a;
  --color-danger: #c73851;
  --color-warning: #9a5a00;
  --color-info: #157a88;
  --color-link: #0b7c79;
  --color-vip: #8a5b20;

  --color-text-primary: #261208;
  --color-text-secondary: #7b6f67;
  --color-text-tertiary: #91867e;
  --color-text-disabled: #c8c2bd;

  --color-page-bg: #fbf9f5;
  --color-surface: #ffffff;
  --color-subtle-bg: #f2f0ec;
  --color-selected-bg: #ede9e4;
  --color-divider: #ebe6df;
  --color-divider-strong: #ded7cf;
  --color-overlay: rgb(38 18 8 / 60%);
  --color-shadow: rgb(38 18 8 / 8%);

  --gradient-brand-soft: linear-gradient(135deg, #d6f4e8 0%, #e5f7f7 100%);

  --radius-sm: 8px;
  --radius-md: 12px;
  --radius-lg: 16px;
  --radius-xl: 24px;

```

### 4.7 对比度基线

- `#261208` 在 `#FBF9F5` 上用于主要文字。
- `#7B6F67` 在 `#FBF9F5` 上可用于普通辅助正文。
- `#08795A` 配白色用于主要按钮和深色品牌状态。
- `#14C773` 与 `#68D8DE` 等亮色背景使用 `#261208` 深色文字。
- `#91867E` 仅用于占位符和非必要信息，必要小字号文本使用 `#7B6F67` 或更深颜色。

## 5. 字体与排版

源文件中可确认字体为 `PingFang SC`，标题使用中高字重。源文件没有独立、完整的字体规范页，因此以下字号为工程化语义基线；项目落地时仍应与对应组件稿核对。

### 5.1 字体族

```css
font-family: "PingFang SC", "Microsoft YaHei", system-ui, -apple-system,
  BlinkMacSystemFont, "Segoe UI", sans-serif;
```

- 中文默认使用苹方或系统无衬线字体。
- 数字、金额和时间不得使用装饰字体。
- 不允许业务页面自行引入未经批准的字体文件。

### 5.2 字重

| Token | 字重 | 用途 |
|---|---:|---|
| `--font-regular` | `400` | 正文、说明、输入内容 |
| `--font-medium` | `500` | 按钮、标签、次级标题 |
| `--font-semibold` | `600` | 页面标题、卡片标题、关键金额 |

避免使用 `700` 以上字重堆叠视觉层级。

### 5.3 字号基线

| Token | CSS px | 建议用途 |
|---|---:|---|
| `--font-size-caption` | `10px` | 极弱辅助信息，仅在空间受限场景使用 |
| `--font-size-assist` | `12px` | 提示、标签、补充说明 |
| `--font-size-body` | `14px` | 默认正文、表单内容 |
| `--font-size-body-strong` | `16px` | 重要正文、按钮、卡片标题 |
| `--font-size-title` | `18px` | 浮层标题、弹窗标题 |
| `--font-size-page-title` | `20px` | 页面主标题 |
| `--font-size-display` | `24px` | 关键价格、结果数字、强展示信息 |

### 5.4 排版规则

- 正文行高建议为字号的 `1.4–1.6` 倍。
- 单行按钮和标签行高由组件高度控制，不手动压缩文字。
- 金额的整数、小数、货币符号允许分级，但基线需对齐。
- 最多使用三级文字层级：主要、次要、提示。
- 多行文本禁止垂直居中；说明文字默认左对齐。
- 文案截断必须有业务规则：单行省略、多行省略或允许换行，不得由布局偶然决定。

## 6. 间距、尺寸与布局

源文件未提供独立间距页。项目统一采用 4px 基础网格，并以组件稿为最终尺寸依据。

### 6.1 间距 Token

| Token | 值 | 用途 |
|---|---:|---|
| `--space-1` | `4px` | 图标与短文字的紧密间距 |
| `--space-2` | `8px` | 组件内部小间距 |
| `--space-3` | `12px` | 表单行、标签组间距 |
| `--space-4` | `16px` | 页面左右边距、卡片内边距 |
| `--space-5` | `20px` | 中等区块间距 |
| `--space-6` | `24px` | 大区块间距 |
| `--space-8` | `32px` | 页面模块分组间距 |

规则：

- 移动页面默认左右安全内容边距为 `16px`。
- 卡片内部间距优先使用 `12px` 或 `16px`。
- 区块间距必须大于区块内部间距。
- 不得出现无语义的 `13px`、`17px`、`19px` 等离散值。

### 6.2 圆角 Token

| Token | 值 | 用途 |
|---|---:|---|
| `--radius-sm` | `8px` | 标签、小型状态块、轻量控件 |
| `--radius-md` | `12px` | 按钮、输入框、列表项 |
| `--radius-lg` | `16px` | 普通卡片、弹窗内容区 |
| `--radius-xl` | `24px` | 大型卡片、底部浮层、首屏重点容器 |
| `--radius-pill` | `999px` | 胶囊按钮、标签、开关 |

同一个组件族必须使用相同圆角，不允许业务页面随意调整。优先通过留白和柔和圆角形成年轻、亲和的视觉，不使用过度膨胀的圆角破坏信息密度。

### 6.3 阴影与边框

| Token | 值 | 用途 |
|---|---|---|
| `--shadow-card` | `0 8px 24px rgba(38, 18, 8, 0.06)` | 需要从暖白画布中轻微抬升的卡片 |
| `--shadow-floating` | `0 16px 40px rgba(38, 18, 8, 0.10)` | 弹窗、气泡、吸底操作区等悬浮层 |

规则：

- 默认通过背景和分割线建立层级，避免大面积重阴影。
- 边框颜色使用 `--color-divider` 或 `--color-divider-strong`。
- 普通白色卡片优先使用边框或 `--shadow-card`，二者不应同时强化。
- 浮层和弹窗优先使用蒙层与 `--shadow-floating` 建立层级。
- 禁止纯黑高透明阴影、彩色霓虹阴影和多层厚重投影。

## 7. 图标规范

源规范明确要求基础图标使用 Iconfont 统一管理，并提供 图标库与 Iconfont 官方库入口。

### 7.1 图标来源

按优先级使用：

1. 项目已接入的 出行图标组件库
2. 同程统一 Iconfont 项目
3. 经过设计确认的新图标

禁止：

- 使用 Emoji 代替正式 UI 图标
- 从不同开源图标库混用风格
- 在业务代码中重复粘贴相同 SVG
- 用图片切图实现可矢量化的基础图标

### 7.2 尺寸与颜色

- 常用视觉尺寸：`16px`、`20px`、`24px`。
- 图标颜色默认继承 `currentColor`。
- 可点击图标的触控热区至少为 `44 × 44px`，视觉图标可以小于热区。
- 线性图标应保持统一描边粗细、端点和圆角风格。
- 禁用图标使用 `--color-text-disabled`，不直接修改整体透明度。

### 7.3 命名

建议使用“对象/动作 + 状态”的语义命名：

```text
arrow-left
close
info-circle
checkbox-checked
checkbox-unchecked
radio-checked
loading
success
error
```

不得使用 `icon1`、`new-icon`、`temp` 等无语义命名。

## 8. 基础组件

源组件库包含按钮、标签、气泡、Toast 等基础组件。

### 8.1 按钮 Button

#### 类型

- `primary`：深青玉实心，页面主要操作；白色文字使用 `--color-brand-strong` 背景
- `secondary`：次要操作，浅色或描边形态
- `text`：低权重文字操作
- `danger`：危险红实心或浅色背景，高风险、删除和强警示操作

#### 尺寸

组件库同时包含大、中、小和迷你形态。工程中建议统一为：

- `large`：页面底部主操作、全宽操作
- `medium`：普通表单和弹窗操作
- `small`：卡片内局部操作
- `mini`：标签式轻操作，谨慎使用

#### 状态

每种按钮必须支持：

- `default`
- `pressed`
- `loading`
- `disabled`

异步提交规则：

1. 点击后立即进入 loading。
2. loading 时禁止重复提交。
3. 文案宽度变化不得导致布局抖动。
4. 请求失败后恢复可操作状态并给出反馈。

#### 内容

- 默认仅使用单行文案。
- 组件库支持主标题 + 副标题按钮，但只用于需要解释价格、权益或操作结果的场景。
- 一个页面或弹窗中只允许一个视觉权重最高的主按钮。
- 特色渐变按钮只用于单一重点入口，使用青绿—青蓝渐变并搭配褐黑文字。
- 普通提交、支付和确认按钮使用深青玉纯色，避免渐变干扰状态识别。

### 8.2 标签 Tag

- 用于状态、推荐、权益和轻量分类。
- 推荐和信息语义使用信息青；品牌标签使用青玉浅色背景；危险标签使用危险红；营销标签优先使用品牌渐变或 VIP 金。
- 标签文字应短，不承载完整句子。
- 同一组标签高度、圆角和内边距一致。
- 不得仅通过颜色传达唯一含义，应同时提供文字。

### 8.3 气泡 Popover

- 气泡由内容容器和统一箭头组件组成。
- 箭头方向必须指向触发源。
- 默认用于短提示或轻量操作，不用于长表单。
- 点击外部区域或完成操作后关闭。
- 气泡不得遮挡当前必须操作的核心内容。

### 8.4 Toast

组件库包含多合一新样式以及成功、失败、加载等状态。

- 普通 Toast 用于低打断的结果反馈。
- 成功与失败状态同时提供图标和文字。
- 加载 Toast 必须能被后续成功或失败状态替换。
- 普通 Toast 自动消失；失败信息需要保留足够阅读时间。
- 重要错误不得只使用 Toast，应在对应输入项或页面区域内展示原因。
- 同一时间只显示一个全局 Toast，新的状态更新旧实例。

## 9. 浮层 Bottom Sheet / Overlay

源组件库将浮层拆分为：基础浮层、插图浮层、文本浮层、浮层顶栏、浮层 Tab 及底栏操作区。

### 9.1 基础结构

```text
Overlay
├─ Mantle / 蒙层
└─ Sheet
   ├─ Header / 顶栏
   ├─ Tabs（可选）
   ├─ Illustration（可选）
   ├─ Content
   └─ Footer / 底部操作区（可选）
```

### 9.2 视觉规则

- 蒙层使用 `rgba(0, 0, 0, 0.60)`。
- 内容区使用白色表面背景。
- 顶部圆角统一使用大型圆角 Token。
- 高度优先由内容决定；超出可视区时内部滚动。
- 底部按钮区需要适配 `safe-area-inset-bottom`。

### 9.3 关闭方式

源规范展示了以下关闭方式：

- 点击蒙层关闭
- 点击关闭按钮关闭
- 下拉顶栏区域关闭

落地要求：

- 仅展示信息的轻浮层可以支持蒙层关闭。
- 有未保存输入、支付或高风险操作时，蒙层点击不得直接丢弃数据。
- 下拉关闭必须有明确的拖拽区域和位移动效。
- 所有浮层至少保留一个无歧义的关闭路径。

### 9.4 Tab 浮层

- Tab 数量过多时允许横向滚动，但首屏需显示当前选择。
- 激活态使用深青玉和清晰指示器；特色场景可以使用青绿—青蓝渐变指示器。
- 切换 Tab 不应关闭浮层或重置无关输入。
- Tab 内容区高度变化时避免浮层整体剧烈跳动。

## 10. 弹窗 Dialog / Modal

源组件库将弹窗拆分为文字、按钮、插图、插槽和操作区，可组合成多种弹窗。

### 10.1 使用场景

弹窗仅用于：

- 需要用户立即确认的关键决策
- 不可逆或高风险操作确认
- 短内容的重要提醒
- 需要在当前上下文完成的轻量任务

非关键说明应优先使用页面内提示、Toast、气泡或浮层。

### 10.2 内容结构

```text
Dialog
├─ Illustration（可选）
├─ Title
├─ Description
├─ Custom Slot（可选）
└─ Actions
```

- 标题直接说明发生了什么或需要用户做什么。
- 描述只保留完成决策所需的信息。
- 插图为可选项，不得挤压关键文案和按钮。
- 自定义插槽不得破坏弹窗统一内边距。

### 10.3 按钮布局

- 单按钮：用于确认结果或知晓型提示。
- 双按钮：主操作 + 取消/次操作。
- 主操作放置位置在同一项目内必须统一。
- 危险操作必须使用危险色和明确动词，不使用模糊的“确定”。

### 10.4 行为规则

- 弹窗出现后焦点进入弹窗，背景不可操作。
- 不允许连续堆叠多个弹窗。
- 异步操作期间按钮进入 loading，防止重复提交。
- 内容过长时优先改用浮层或独立页面。

---

## 11. 输入与选择组件

源组件库包括输入框、滑动选择器、评分器、步进器、开关、勾选、单选框和复选框。

### 11.1 通用状态

所有输入组件必须支持：

- 默认 `default`
- 聚焦 `focus`
- 已填写 `filled`
- 错误 `error`
- 禁用 `disabled`
- 只读 `readonly`（业务需要时）

### 11.2 输入框 Input

推荐结构：

```text
Label
Input Row
├─ Prefix（可选）
├─ Value / Placeholder
├─ Clear（可选）
└─ Suffix（可选）
Helper / Error
```

规则：

- Label 不得仅依赖 placeholder。
- placeholder 使用三级文字色。
- 错误信息展示在当前字段附近，并说明修复方式。
- 清除按钮只在有内容且允许清空时展示。
- 金额、手机号、证件号等使用正确键盘类型与格式化策略。
- 输入内容不得因为格式化导致光标异常跳动。

### 11.3 滑动选择器 Slider

- 激活轨道使用深青玉，未激活轨道使用暖灰浅色。
- 拖拽点热区大于视觉尺寸。
- 有精确值要求时同时显示数值或刻度。
- 禁止仅依赖拖动完成无障碍操作，应提供替代输入能力。

### 11.4 评分器 Rating

- 已选状态使用品牌或业务指定强调色，未选状态使用中性浅色。
- 支持整数评分；半星能力必须由需求明确。
- 点击区域覆盖完整星形单元。
- 评分后需要清晰反馈当前值。

### 11.5 步进器 Stepper

- 包含减少、数值、增加三个区域。
- 达到上下限时对应按钮进入禁用态。
- 数值变化后立即反馈价格或库存影响。
- 连续点击不得产生越界值。

### 11.6 开关 Switch

- 只用于即时生效的二元状态。
- 需要提交确认的选择不得伪装成开关。
- 激活态使用深青玉，禁用态使用禁用色。
- 开关旁必须有可理解的文字标签。

### 11.7 单选与复选

- 单选用于互斥选项；复选用于多选。
- 文案和控件整体均可点击。
- 选中状态使用深青玉，并同时有形状或图标变化。
- 不允许使用仅颜色变化的不可辨识状态。

---

## 12. 表单与流程组件

源组件库包含步骤器、节点状态和卡片表单。

### 12.1 卡片表单

- 使用白色卡片承载一组强相关字段，页面底层使用暖白背景。
- 卡片之间通过暖白页面背景、轻边框和模块间距分组。
- 标签、值、辅助信息和操作保持统一对齐。
- 不应为每一个字段创建独立卡片。

### 12.2 步骤器 / 流程节点

节点至少包含：

- 未开始
- 当前进行中
- 已完成
- 异常或失败
- 禁用或不可达（业务需要时）

规则：

- 当前步骤必须同时通过颜色和结构突出。
- 已完成与当前进行中不得使用完全相同的状态。
- 错误步骤展示原因或可操作入口。
- 移动端步骤过多时使用简化标题或可滚动结构，不强行压缩。

### 12.3 校验与提交

- 优先在失焦或提交时校验，避免用户尚未输入就显示错误。
- 首次提交失败后滚动并聚焦第一个错误字段。
- 提交中锁定主按钮，避免重复请求。
- 保留用户已填写内容，接口失败不得清空表单。

---

## 13. 品宣与品牌组件

源文件提供了同程机票品牌背书、服务卖点和“马达出行”等品宣组件。

规则：

- 品牌 Logo、组合文案、图形比例和服务卖点必须直接复用设计系统组件。
- 不得自行重绘、拉伸、换色或调整 Logo 字距。
- 品牌签名应作为完整组件使用，不拆分后重新排列。
- 深浅背景使用对应版本，保证品牌标识对比度。
- 不同渠道的品牌组合必须由渠道配置选择，不在页面中硬编码。
- 营销口号更新时应修改组件源，而不是逐页面替换。

## 14. 系统栏与安全区

源组件库包含活动条与标题栏；温润青玉主题覆盖暖白背景、深青玉背景、特色渐变背景、有标题和无标题等形态。

### 14.1 标题栏

支持：

- 返回按钮 + 居中标题 + 小程序胶囊区
- 返回按钮 + 无标题 + 胶囊区
- 暖白背景、深青玉背景与特色渐变背景
- 自定义标题栏

规则：

- 返回按钮必须位于安全操作区。
- 标题在视觉上居中，不因左右操作数量不同而偏移。
- 深青玉背景使用白色标题和系统图标。
- 青绿—青蓝亮色渐变背景默认使用褐黑标题和系统图标，并逐屏检查对比度。
- 浅色背景使用主要文字色。
- 自定义标题栏需兼容不同平台的状态栏和胶囊尺寸。

### 14.2 安全区

```css
.page-bottom-action {
  padding-bottom: max(16px, env(safe-area-inset-bottom));
}
```

- 顶部内容避开状态栏、刘海和小程序胶囊。
- 底部吸附操作避开 Home Indicator。
- 不将安全区高度写成单一设备常量。

## 15. 动效与反馈

源文件没有独立动效页，以下为与组件行为匹配的工程基线。

- 普通状态切换：`150–200ms`
- 浮层进入/退出：`200–300ms`
- Toast 淡入淡出：`150–200ms`
- 动效曲线优先使用标准 ease-out 进入、ease-in 退出。
- loading 动画必须循环平滑且不造成布局位移。
- 尊重系统“减少动态效果”设置。
- 禁止无业务意义的弹跳、长距离移动和循环装饰动画。

---

## 16. 响应式与多端适配

### 16.1 布局原则

- 以移动端单列布局为默认。
- 内容宽度由容器控制，不以固定设备截图宽度实现。
- 窄屏优先保证主要操作与核心信息，不横向压缩文字。
- 长文案、英文、数字串和动态价格必须进行极端值测试。

### 16.2 平台差异

平台差异应封装在系统组件或适配层中：

- 状态栏与标题栏高度
- 小程序胶囊位置
- 底部安全区
- 键盘顶起与输入滚动
- 原生返回手势
- 系统字体缩放

业务页面不得散落平台判断来重复计算系统栏尺寸。

---

## 17. 无障碍要求

- 普通正文与背景对比度至少达到 WCAG AA。
- 重要文字和图标不得使用过浅的青玉或青蓝色阶。
- 触控目标建议至少 `44 × 44px`。
- 状态不得只通过红绿颜色区分。
- 图标按钮必须提供可访问名称。
- 表单字段需要程序化 Label、错误描述和焦点状态。
- 弹窗打开后焦点限制在弹窗内，关闭后返回触发源。
- Toast 等动态消息应通过合适的 live region 通知辅助技术。

## 18. 组件工程约束

### 18.1 复用顺序

实现新页面前按以下顺序判断：

1. 项目是否已有相同组件
2. 出行组件库是否已有对应组件
3. 是否可通过现有组件的受控变体解决
4. 最后才允许新建组件

不得复制现有组件代码后改名形成分叉版本。

### 18.2 组件 API

组件属性使用语义值，不暴露任意视觉值：

```ts
// 推荐
<Button variant="primary" size="large" loading />
<Tag tone="recommend">推荐</Tag>

// 不推荐
<Button color="#08795A" radius={9} height={43} />
```

### 18.3 样式管理

- 颜色、字号、间距、圆角统一来自 Token。
- 组件内部禁止读取业务页面的任意 class 约定。
- 组件变体应有限、可枚举并有视觉稿依据。
- 渠道主题通过 Theme Token 切换，不复制整套组件。

### 18.4 推荐目录

```text
src/
├─ design-tokens/
│  ├─ colors.ts
│  ├─ typography.ts
│  ├─ spacing.ts
│  ├─ radius.ts
│  └─ theme.ts
├─ components/
│  ├─ button/
│  ├─ tag/
│  ├─ toast/
│  ├─ popover/
│  ├─ dialog/
│  ├─ bottom-sheet/
│  ├─ input/
│  ├─ selector/
│  ├─ stepper/
│  ├─ form/
│  └─ system-bar/
└─ assets/
   ├─ icons/
   └─ brand/
```
